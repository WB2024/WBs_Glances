## Addendum: changes made after the reference above was written

These came out of the first round of real-world testing. Where this addendum and the text above disagree, this addendum wins.

- **Locked widgets hide their name.** While locked, a `wb-restricted` widget shows the title "Private" with no link (`maskTitle()` in `wb-restricted.js`); the real title and link come back after the PIN. Container, app and repository names that belong to private apps are flagged `private` by glance-admin (`PRIVATE_STACKS` regex) and are only listed inside locked widgets.
- **Infra** lists *every* physical disk on the Proxmox hosts (model, size, SMART health, SSD life left, what it is used for) from the Proxmox API, the real per-mount usage where a host agent reports it, and a diagram that shows every drive and mount. The role text for each disk is the `ROLES` table in `glance-admin/infra.py`: edit it when drives change. Per-mount usage for pve4 comes from an optional read-only service, `glance-disks` (`scripts/proxmox-host/`, systemd, port 27975, bearer token `AGENT_TOKEN_PVE4`); without it the list still shows model, size, health and role.
- **Audio**: Audiobookshelf shows *Continue listening* plus one random row per open library (the sample changes each time Glance refreshes the widget). The locked library row is titled "Audiobookshelf - More".
- **Networking**: the Nginx Proxy Manager widget lists problems (backend down / disabled) always, and every proxy host inside a collapsed "All proxy hosts" list.
- **Cameras**: *Recent detections* (30), *Detections by type* (one row per object type, e.g. person, car, cat), a 24-hour activity chart, and **Search detections by date and time**: pick a type, a camera and a range (last hour / 6 h / 24 h / 7 days / custom from-to) and scroll the results sideways. Search runs through `GET /api/cameras/events`, which validates every parameter before passing it to Frigate.
- **Cameras search** (`cam-events` in `wb-home.js`, `GET /api/cameras/events?q=&mode=`, `/api/cameras/event`, `/api/cameras/clip`): semantic search through Frigate (`description` or `thumbnail` mode), results as a grid, a viewer with snapshot / clip / description. Clips are fetched through glance-admin because Frigate streams them chunked with no length or ranges and tags HEVC as `hev1`; glance-admin serves them with proper headers and range support and re-tags `hev1` as `hvc1`. The Detections-by-type widget was removed from the page.
- **Tools cards**: the tile list is replaced by one card per tool (`gen_tools.py`, `glance-admin/tools.py` `cards()`): Kiwix, SearXNG, NOMAD, Kolibri, Stirling PDF, Flatnotes, Homebox, and a remote-apps/vault card, each with its container's status, CPU and RAM. CPU and RAM come from a new read-only `GET /stats?names=` on the glance-lister (names validated, numbers only). Update notices come from NOMAD's service list.
- **Shopping** tab (`gen_shopping.py`, `glance-admin/shop.py`, `wb-home.js` components `shop-*`, `/api/shopping/*`): list, wishlist (target prices, optional link to a price watch), locked gift ideas, purchases and spend chart, deal alert words, saved eBay searches (official Browse API, needs EBAY_APP_ID/EBAY_CERT_ID), price/stock watches (changedetection.io in `stacks/changedetection`, `restock_diff` processor, one check every 6 hours), Discogs, rpilocator stock, deals from HotUKDeals and Reddit RSS (Reddit is fetched rarely because it rate-limits). State is `data/shopping.json`; slow external data is cached and refreshed in the background, and changes you make trigger an immediate refresh.
- **Carousels** (Glance's video rows and the cover strips) have left/right buttons on desktop; touch screens swipe. Added by `addArrows()` in `wb-home.js`.
- **Video News Feed**: each channel in the *Channels* box has a **Remove** button (click twice to confirm); adding is unchanged. Both go through glance-admin and regenerate the page file.
- **News Feeds** is now generated by glance-admin (`news.py`, state in `data/news.json`, page file `config/data/news.yml`). The **Feeds** box at the top of the middle column adds RSS feeds (it verifies that the address really is a feed, and will follow a page's "alternate feed" link) and subreddits (r/name; Reddit often refuses checks from servers, so an unconfirmed name is added with a warning), into any existing group or a new one, and removes them again. `tools/gen_news.py` is retired.
- **Bookmarks**: a group can be marked *private*; it is then rendered in its own locked widget ("Private bookmarks"). The Edit bookmarks panel only lists private groups, and only lets you add to them, while the page is unlocked in this tab. This is as strong as the other locks: casual privacy, not security.
- **Dev** tab (`gen_dev.py`, `glance-admin/dev.py`, `GET /api/dev/summary`): GitHub (profile, repos, events, PRs/issues, Actions runs, GraphQL contribution graph, language mix, API budget) and Forgejo (repos with last commit, heatmap, activity, issues), CI status, dev-tool tiles and recipe links, dev search. Private repositories/events are returned in a separate `private` block that only a locked widget renders and that is stripped before anything is cached to disk. The Forgejo card moved here from Tools, together with the CyberChef / IT Tools / Excalidraw / Dozzle / Termix tiles.
- **Page warmer**: glance-admin requests every page every 15 s (`WARM_SECONDS`, 0 = off) so Glance's widget caches are always fresh and tabs open instantly.
- **VPN control** (Networking tab; `glance-admin/vpn.py`, `GET /api/vpn/summary`, `POST /api/vpn/command`, `vpn` component in `wb-home.js`, `gen_networking.py`): one card per machine running the [WBs-VPN-Dashboard](https://github.com/WB2024/WBs-VPN-Dashboard) agent, showing connected / disconnected, country and city, with a country dropdown, Connect / Switch / Disconnect, Kill switch and Tailscale toggles, and a **DNS** selector (Nord DNS / Local names via Pi-hole / Pi-hole for everything: see the WBs-VPN-Dashboard README for why Nord's own custom DNS cannot reach a LAN Pi-hole). glance-admin forwards to the panel (`VPN_URL`, `VPN_KEY` in `stacks/glance-admin`); the panel's API key never reaches the browser. Writes are allow-listed (connect with a country, disconnect, two on/off toggles, the DNS mode), must come from the same host as glance-admin (`Origin` check, extra hosts via `VPN_ORIGINS`) and must send the `X-WB-VPN` header, which forces a CORS preflight so a page on another site cannot trigger them. The agent undoes a connect that leaves the machine without the panel, DNS or internet (rolls back and reports why), keeps the LAN and Tailscale allowlisted, and refuses the kill switch while disconnected. Changes to `custom.css` show up only after Glance reloads its config (the asset URL carries a version), so restart the `glance` container after editing it.
- **Remote** tab (`gen_remote.py`, `glance-admin/remote.py`, `GET /api/remote/hosts`, `GET /api/remote/metrics?id=N`, `remote-workspace` component in `wb-home.js`): a workspace for every host defined in [Termix](https://github.com/Termix-SSH/Termix), so adding a host there adds it here. Left: searchable host list (Recent from Termix's audit log, then folders, then remote desktops) with Termix's own online/offline status. Right: open sessions as chips, a tab per capability the host has in Termix (Terminal; Files if the file manager is enabled; Docker; Metrics; Tunnels; Tmux; or an inline VNC/RDP desktop), live CPU / RAM / disk / load / uptime, Reload, Pop out, Full screen, and **Split** (two sessions side by side). Each pane is one of Termix's standalone views (`?view=terminal|file-manager|docker|host-metrics|tunnel|tmux_monitor|vnc|rdp&hostId=N`) in a sandboxed iframe (no `allow-modals`, so Termix's leave-page prompt cannot appear), created on first use and then kept alive while you stay on the page, so switching hosts or tabs does not drop a shell. Glance tabs are full page loads, so leaving the Remote tab ends the sessions. Deep link: `/remote?host=11&tab=files`. File access goes through Termix's own login, not glance-admin. glance-admin reads Termix with an API key (`TERMIX_URL`, `TERMIX_API_KEY` in `stacks/glance-admin`; the key never reaches the browser); the host list is cached 15 s, metrics 10 s, and the last good list is served (marked stale) if Termix stops answering. Termix must be opened with the **same hostname** as Glance (its login cookie is per host; only the port differs), so the browser builds the address from `location.hostname` and `REMOTE_TERMIX_PORT` (default 8080); if a pane asks you to log in, use the "Termix" button once. Newer Termix releases may send `X-Frame-Options: DENY`; if panes go blank use Pop out, or strip the header in the reverse proxy. Wake-on-LAN is not implemented (no host in Termix has a MAC address).
- **Work** tab (`gen_work.py`, `glance-admin/work.py`, `GET /api/work/summary`, `/api/work/search?q=`, `/api/work/order?id=`, `work-search` and `work-refresh` components in `wb-home.js`, `.wb-wk-*` styles): one page for a business's systems, fed by read-only API calls from glance-admin. **Brightpearl** (sales orders with GBP totals, revenue and orders per day, channels, destinations, top products, order status board, orders waiting on payment, purchase orders), **HubSpot** (open pipeline by stage and owner, won per month, deals closing soon and gone quiet, new contacts per day and source, support tickets, tasks, meetings, domains), **WordPress / WooCommerce** (revenue, orders to ship, best sellers, catalogue stock, site response time, content counts, recent posts) and **PythonAnywhere** (CPU quota, web apps, scheduled tasks with next run, error-log tail). *Business pulse* and *Needs attention* combine all four. The page builds one cached document every 5 minutes (`work_loop`; the Refresh button forces a rebuild, rate-limited to one per 20 s); each system is an independent section (`bp`, `hs`, `wp`, `pa`, each with `ok` / `err`), so one outage only greys out its own cards. HubSpot's search API allows about 4-5 calls a second, so `work.py` spaces its calls and honours `Retry-After`; Brightpearl is throttled by its own request budget (shown in the Systems card). Clicking an order opens an order viewer, and the search box looks up HubSpot contacts / companies / deals, WooCommerce orders and Brightpearl order numbers or customer references. Keys are the `WORK_*` variables (see `.env.example`); site addresses used in links come from `WORK_WP_URL`, `WORK_PA_USER` and `WORK_HS_PORTAL`, so nothing business-specific is written into the repo. Privacy: marketplace buyers' names, addresses and e-mail addresses are never shown, and the summary is cached on the server only (`data/cache`, excluded from the repository export). The page has no sign-in of its own; the numbers are visible to anyone who can open Glance.
